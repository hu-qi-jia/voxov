# 面试助手（Interview Assistant）设计文档

- 日期：2026-10-04（v1.1，第三方评审后修订）
- 状态：已与用户逐节评审通过
- 项目性质：开源 PC 客户端，单机使用，无鉴权、无用户体系

## 1. 背景与目标

求职者在技术面试（技术八股 + 项目经历类，中文为主）中需要实时辅助：客户端持续监听系统音频（会议软件播放出的面试官声音），转写为字幕，用户按热键触发后，基于个人向量知识库检索并生成"可直接照读"的口语化要点答案，显示在置顶悬浮窗中。

**第一优先级：热键 → 答案首字的延迟。** 所有设计决策围绕"面试节奏下可用"展开。
**第二优先级：隐蔽性。** 该工具在他人屏幕共享/录屏视角下必须可瞬间隐身。

### 成功标准

- 热键按下 → 答案首字显示 ≤ 2 秒（常态）
- 热键按下时问题文本完整（含刚说完的最后一句）
- 中文学术/技术术语识别准确（术语识别错误会直接污染检索）
- 答案为口语化分点格式，用户无需脑内翻译即可照读
- 急隐藏热键可在 <100ms 内让一切可见痕迹消失
- 知识库入库、面试记录导出全流程不依赖网络（除 LLM 调用）

### 目标硬件画像

小显存 N 卡 + 较强 CPU 的 Windows PC。本地模型按 CPU int8 实时档位选型，不依赖 GPU。

## 2. 需求汇总

| 维度 | 结论 |
|---|---|
| 核心场景 | 真实面试实时辅助 |
| 面试类型 | 技术八股 + 项目经历类，中文为主 |
| 交互 | 持续转写字幕 + 全局热键触发生成（半自动，避免寒暄误触发）；默认热键 `Ctrl+Alt+Space` |
| 急隐藏 | `Ctrl+Alt+H` 一键隐藏悬浮窗与托盘（§6.5） |
| 展示 | 置顶悬浮窗：实时字幕 + 流式答案，可拖动、可调透明度 |
| 音频范围 | **仅采集系统音频（面试官侧）；不采集麦克风，作答者声音不入库不入记录**（§2.1） |
| LLM | OpenAI 兼容接口（用户自配 base_url / api_key / model） |
| 设置 | 全部配置集中在独立设置页：LLM、模型/数据目录、热键、急隐藏热键、音频设备（§6.7） |
| UI | ChatGPT/Meta 式暗色科技风，集中设计令牌，界面零解释性文案（§6.8） |
| MVP 范围 | 核心链路 + 追问多轮上下文 + 实时字幕 + 面试记录导出 + 急隐藏 + 彩排模式 |

### 2.1 音频范围（显式约束）

提问方（面试官）声音经会议软件播放，由 WASAPI loopback 采集系统输出获得。会议软件默认**不回放**本地麦克风，因此系统音频天然只含对方声音，无需说话人分离。作答者（用户）的语音不采集、不转写、不记录；多轮上下文中的"之前的回答"以**生成答案**作为作答记录的代理（用户实际所说以生成为准的近似）。

### 非目标（本期不做）

- 麦克风输入（含"把用户回答也转写"——见 §2.1，明确不做）
- 全自动"听题即答"触发模式
- 说话人分离
- 英文面试双语检索优化（SenseVoice 自带中英混合识别，够用）
- 算法题/代码屏幕理解
- 鉴权、多用户、云同步
- 八股仓库一键导入（v1.1 候选）

## 3. 技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 语言/形态 | Python 单体 + PyInstaller 打包 exe | 一种语言；ASR/embedding 生态原生；开发最快 |
| UI | PySide6 + 集中式 QSS 主题 | 悬浮窗（置顶/透明度/拖动）、托盘、多窗口；主题见 §6.8 |
| 音频采集 | pyaudiowpatch（WASAPI loopback） | Windows 系统音频捕获现成方案，免驱动 |
| ASR | FunASR `AutoModel`：SenseVoice-Small（int8）+ FSMN-VAD + CT-Transformer 标点 | 中文 CER 约为 Whisper 系一半；非自回归一次前向出整句，CPU 实时；VAD 和标点流水线自带 |
| Embedding | BAAI/bge-small-zh-v1.5（sentence-transformers，本地） | 中文语义检索轻量档，CPU 编码 ~50ms |
| 向量库 | SQLite 单文件：sqlite-vec（向量）+ FTS5 trigram（全文） | 个人级库（数百篇 md）零部署；trigram 支持中文子串匹配 |
| LLM 客户端 | httpx，OpenAI 兼容 `/chat/completions`，SSE 流式 | 用户自配任意兼容服务商 |
| 全局热键 | keyboard 库 | Windows 全局热键成熟方案 |

不 fork 任何上游开源项目，全部作为库引用，自己写的只有胶水层和 UI。

### 模型体积预算（int8，合计 < 1 GB）

| 模型 | 用途 | 大小 |
|---|---|---|
| SenseVoice-Small | 语音识别 | ~240 MB |
| FSMN-VAD | 语音分段 | ~5 MB |
| CT-Transformer | 标点恢复 | ~80-150 MB |
| bge-small-zh-v1.5 | 向量化 | ~100 MB |

### 路径约定（设置页可改）

- 模型目录：默认 `<项目根>/models/`（打包后为 exe 所在目录下 `models/`，绿色便携）
- 数据目录：默认 `<项目根>/data/`（`kb.db` + 面试记录）
- `models/`、`data/` 必须写入 `.gitignore`（模型 0.5GB + 个人面试记录属隐私，不得入库）
- 模型下载支持 HF 镜像（`HF_ENDPOINT=https://hf-mirror.com`），首次启动向导式下载，含进度与断点续传

```
interview-assistant/

│   ├── main_window.py        # 主窗口：知识库管理 + 监听/彩排/导出控制（设置入口）
│   ├── settings_dialog.py    # 设置页：LLM / 目录 / 热键 / 急隐藏 / 音频设备（§6.7）
│   ├── overlay.py            # 置顶悬浮窗：实时字幕 + 流式答案
│   ├── wizard.py             # 模型下载向导
│   ├── tray.py               # 托盘：开始/停止监听、退出
│   └── theme.py              # 设计令牌 + QSS 生成（§6.8）
├── core/
│   ├── capture.py            # AudioSource 接口：LiveAudioSource / WavFileSource（彩排/测试）
│   ├── transcriber.py        # FunASR AutoModel 封装（VAD + SenseVoice + 标点）
│   ├── kb.py                 # md 解析切分 + 向量化 + sqlite-vec/FTS5 存储
│   ├── retriever.py          # 混合检索 + RRF 融合
│   ├── generator.py          # LLMClient 接口：OpenAI 兼容 SSE 流式 + prompt 组装
│   ├── session.py            # 会话状态：转写缓冲（带时间戳）、多轮上下文、导出
│   ├── pipeline.py           # 实时管线：采集→分段→转写→缓冲（含 flush_pending）
│   └── downloader.py         # 模型下载（镜像、跳过已有、断点续传）
├── hotkey.py                 # 全局热键 + 急隐藏热键
├── main.py
└── pyproject.toml
```

### 线程模型（延迟的关键）

- **音频线程**：WASAPI loopback 采集 16kHz 单声道 → 环形缓冲（只保留最近 60s，防积压）
- **ASR 线程**：能量 VAD 分段 → 逐段转写 → 结果（带时间戳、停顿边界）追加会话转写缓冲
- **UI 主线程**：悬浮窗/主窗口渲染、热键回调转发
- **生成 worker 线程**：热键触发后执行 强刷管线 → 提取问题 → 检索 → LLM 流式生成，逐 chunk 经 Qt 信号回传 UI

### 数据存储

单文件 `kb.db`：

- `chunks` 表：chunk 文本、标题路径（如 `Redis > 持久化 > RDB`）、来源文件、序号
- sqlite-vec 虚拟表：512 维向量（bge-small-zh）
- FTS5 trigram 虚拟表：chunk 文本全文索引

会话记录（导出用）：`data/sessions/<日期>-<时间>.json`，存 `(时间戳, 转写文本, 触发的问题, 检索来源, 生成的答案)`。

## 5. 数据流

### ① 知识库入库（面试前，主窗口）

上传 md → 结构感知切分（见 §6.1）→ bge-small-zh 批量向量化 → 写入 kb.db。重复上传同名文件 = 事务内全量替换该文件的 chunks。

### ② 实时辅助（面试中）

系统音频持续采集 → ASR 增量转写 → 悬浮窗滚动显示最近几条字幕。用户确认字幕后按热键 → **强制 flush 管线 pending 语音（§6.6）** → 回溯提取问题（见 §6.4）→ 混合检索 top5 → 组装 prompt（问题 + 检索片段 + 最近 2 轮问答）→ LLM 流式生成 → 悬浮窗逐字显示。

### ③ 记录导出（面试后）

一键将当前会话 JSON 导出为 md 复盘文件（含检索来源标注）。

### ④ 彩排模式（面试前，主窗口）

选择一段会议录音 wav → `WavFileSource`（按真实时长回放）走与 ② 完全相同的实时链路（不接真实设备）→ 验证字幕质量、检索命中、延迟与热键手感。彩排会话默认标记为 rehearsal，不写入正式面试记录目录（独立 `sessions/rehearsal/` 子目录）。

## 6. 关键设计细节

### 6.1 md 切分（结构感知）

- 按标题层级切 section（`#`→`##`→`###`），section 内段落聚合至目标 **300-500 字/块**
- 相邻块重叠 ~50 字
- **代码块、表格永不切断**：代码块与其前导说明文字合并为同一 chunk
- 元数据：标题路径 + 来源文件 + 块序号

### 6.2 混合检索

- 向量检索 top5（查询用同一 bge-small-zh 编码）
- FTS5 trigram 关键词 top5（术语精确匹配：`SORT 命令`、`MVCC` 等字面命中比语义相似可靠）
- RRF 融合（k=60），取前 5
- 兜底：检索片段不足或知识库为空时不阻塞，prompt 中让模型优先用参考资料、不足时用自身知识并标注"通用回答"

### 6.3 Prompt 设计（口语化照读）

System 提示词：

> 你是面试实时辅助。输出口语化中文，像求职者当场回答，可直接照读，禁止书面腔和套话开场。分点输出，每点一句完整的话，关键词加粗。按重要性排序，最重要的点放第一条。共 4-6 点，全篇不超过 250 字。优先使用参考资料，资料不足时用自身知识。

- 上下文 = 问题 + 检索片段（带来源标注）+ 最近 2 轮 (Q, A)（支撑"那如果数据量再大呢"类追问；A 取生成答案，见 §2.1）
- 参数：temperature 0.3，max_tokens 500（硬上限防小作文）
- 要点按重要性排序 + 流式渲染 ⇒ "能开口"时间 ≈ 首 token + 1 秒

### 6.4 热键问题提取（回溯算法）

转写缓冲区每条带时间戳与段边界。按热键时：从当前位置回溯找 **≥1.5 秒停顿点**，取停顿之后的全部文本为当前问题；30 秒内无停顿则取最近 30 秒文本。寒暄、上一问不会混入（用户自己的声音根本不采集，见 §2.1）。

### 6.5 急隐藏（stealth 层）

- **急隐藏热键** `Ctrl+Alt+H`：<100ms 内隐藏悬浮窗、托盘图标；再按一次恢复
- 对外可见痕迹中性化：打包进程名与 exe 名为 `notes-viewer`；主窗口/悬浮窗窗口标题为 "Notes"；托盘 tooltip 为 "Notes"；README 说明如何自定义
- 知识库/会话数据本就在 `.gitignore` 与 `data/` 内，不产生额外可见痕迹
- 不做（也不建议做）反检测对抗：本项目定位为个人效率工具

### 6.6 热键强刷（竞态修复）

管线需 ~1.2s 静音才把语音段刷入转写缓冲；用户常在问题结束后的 1 秒内按键，此时缓冲缺最后一句。**热键路径必须先调用 `pipeline.flush_pending()`**（对 pending 语音缓冲加锁拷贝后立即转写入缓冲），再执行 §6.4 提取。flush 与管线线程共用同一把语音缓冲锁，保证不丢块不重复。

### 6.7 设置页（全部配置集中于此）

独立 `SettingsDialog`，主窗口仅放"设置"入口按钮。分组：

| 分组 | 项 |
|---|---|
| LLM | base_url、api_key（密码框）、模型名 |
| 存储 | 模型目录、数据目录（目录选择器，改后重启生效） |
| 热键 | 触发热键（默认 `ctrl+alt+space`）、急隐藏热键（默认 `ctrl+alt+h`） |
| 音频 | 输出设备下拉（`list_loopback_devices()`，默认勾选系统默认） |

保存 = 写回 `AppConfig` + `data/config.json`；主窗口不再有任何散落的配置控件。

### 6.8 UI 设计语言（ChatGPT/Meta 式科技风）

- **暗色主题为唯一主题**。设计令牌集中于 `app/theme.py`：背景/表面/悬浮层三级灰、单一强调色（`#10a37f` 系）、边框、文字两级（主/次）、圆角、字体栈（Segoe UI / Microsoft YaHei UI）
- **发行级组件要求**：所有交互控件必须有 hover / pressed / disabled / focus 四态样式；统一圆角与间距节奏；QTableView/QLineEdit/QPushButton/QMenu 全部纳入 QSS 管辖，无原生灰控件
- **文案极简**：界面只出现操作标签（"上传"、"设置"、"导出"）与状态词（"监听中"、"已停止"），**零解释性文案**——不写"点击此处上传您的知识库文件以进行向量化"这类句子；帮助信息一律进 README
- 悬浮窗视觉：半透明深色卡片、无边框、答案区等宽适中，字幕次级灰、答案主文字色、状态词用强调/警示色

## 7. 延迟预算（热键 → 答案首字）

| 环节 | 耗时 |
|---|---|
| 强刷 pending 语音（§6.6） | 100-400 ms（短段转写） |
| 问题提取 | ~0 ms |
| 查询向量化（CPU） | ~50 ms |
| 检索（向量 + FTS5 + RRF） | ~10 ms |
| LLM 首 token | 0.5-2 s |
| **合计** | **0.7-2.5 s** |

ASR 主体持续后台进行，不占用热键后链路时间。

## 8. 错误处理

| 场景 | 处理 |
|---|---|
| 首次启动无模型 | 向导式下载：清单+大小、HF 镜像、进度、断点续传 |
| LLM 调用失败 | 自动重试 1 次 → 状态词提示 + 手动重试，不崩溃 |
| 音频设备热插拔 | 采集层自动重连（最多 3 次，间隔 2s），仍失败才提示 |
| CPU 满载 ASR 积压 | 环形缓冲丢弃旧音频（保留最近 60s），字幕标记延迟 |
| 知识库为空 | 照常生成（纯 LLM），悬浮窗标注"通用回答" |
| API key 未配置 | 触发生成时引导跳转设置页 |
| 上传非 md/损坏文件 | 入库前校验，行级报错并定位到文件 |
| 彩排选错文件（非 wav/损坏） | 打开前校验格式，状态词提示 |

## 9. 测试策略

两个可测性抽象是关键：

- `AudioSource` 接口：live 设备实现 / **wav 文件重放实现**（集成测试与彩排模式共用）
- `LLMClient` 接口：真 API / 本地 mock（验证 SSE 流解析）

测试分层：

- **单元（pytest）**：切分（多级标题/代码块/表格/超长段落/嵌套围栏）、问题回溯提取（时间戳序列）、RRF 融合、prompt 组装与多轮截断、**flush_pending 语音锁语义**、主题令牌完整性
- **集成**：wav 回放 → 转写缓冲 → 热键模拟（含强刷）→ 检索 → mock LLM，断言全链路产物
- **手工验收硬指标**：热键→首字 ≤2s（彩排模式下测）；真实会议回放全链路，术语识别准确、检索命中（用一份已知答案的八股题集验证 top5 命中率）；急隐藏 <100ms；屏幕共享场景下隐藏后无可见解

## 10. 发布形态

- PyInstaller 单文件夹打包（`--onedir`），**exe/进程名 `notes-viewer`**（README 说明）
- exe 同目录下 `models/`、`data/`，整目录拷贝即迁移
- 开源仓库不含模型与数据（.gitignore），首次运行引导下载
- README 含：仅采集系统音频不采集麦克风的说明、急隐藏用法、彩排用法、API key 明文存储提示、免责声明（仅供个人学习与练习用途，使用者自担合规风险）
